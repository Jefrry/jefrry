# Портфолио и резюме — итоги grill-with-docs

Статус: интервью завершено, продуктовое направление согласовано. Документ фиксирует договорённости и контекст для последующей спецификации; он не является спецификацией или планом реализации.

## Цель и аудитория

Персональный сайт Егора Ильина для работодателей и потенциальных заказчиков-нанимателей. Сайт представляет профессиональный опыт, навыки, портфолио, резюме и контакты.

Домен: **https://jefrry.dev**.

## Источник дизайна и фактов

Референс находится в `portfolio-v2-stars/`. Это адаптивный макет на HTML, CSS и JavaScript с навигацией через hash-адреса. Он служит визуальной основой, а не ограничением на точное воспроизведение.

- `dist/index.html` — оболочка, навигация и контакты.
- `dist/app.js` — страницы, тексты, проекты и опыт работы.
- `dist/style.css` — оформление и анимации.
- `dist/assets/whale.png` — изображение кита.
- `dist/assets/stars.svg` — звёздный фон.
- `dist/assets/egor-ilin-resume.pdf` — существующее резюме.

Папка референса исключена из Git существующим `.gitignore`. Для дальнейшей работы важно сохранить доступ к исходнику; готовый проект должен содержать собственные необходимые материалы.

## Визуальное направление

- Сохранить узнаваемый характер референса: тёмный сине-фиолетовый фон, светлый текст, голубые акценты, звёзды и кит.
- Разрешены улучшения композиции, адаптивности, доступности и взаимодействий.
- Обязательно сохранить плавное движение кита. В референсе изображение покачивается и перемещается по вертикали.
- Учитывать системное предпочтение уменьшенного движения.
- Переключатель языка разместить в шапке и сделать доступным на мобильных экранах.

## Состав сайта и контент

### Главная

Сохранить содержимое исходной главной: представление автора, специализацию, местоположение и удалённую работу, контакты, опыт работы, технологии и подход, образование и интересы. Факты профессионального опыта не заменять вымыслом.

Исключения из требования «оставить всё»: любые показываемые проекты используют тестовый набор; статьи полностью скрыты.

### Проекты

- Нужны каталог с фильтрами и отдельные страницы проектов.
- Использовать вымышленные проекты во всех местах сайта, включая возможные подборки на главной.
- Названия и описания должны прямо говорить, что это тестовые данные; отдельная плашка «Демонстрационный проект» не нужна.
- Не приписывать автору вымышленных заказчиков и коммерческие результаты.
- Названия, описания, технологии, обложки и другие материалы должны легко заменяться без изменения компонентов.
- Конкретные имена и тексты тестовых проектов пока не согласовывались и не являются результатом интервью.

### Статьи

- Подготовить заготовки каталога статей и отдельной статьи с тестовыми данными.
- В первой версии раздел полностью выключен: нет пункта меню, блоков, карточек и ссылок на статьи на любых страницах.
- Выключенные страницы не должны публиковаться и попадать в sitemap.
- Согласован механизм общей настройки включения раздела вместо необходимости раскомментировать несколько файлов. Включение потребует новой сборки.

### Резюме

- На русской и английской версиях использовать существующий русский PDF.
- Предусмотреть простую замену файла и возможность назначить отдельный PDF для английской версии позднее.
- Подготовка нового английского PDF не входит в текущие договорённости.

## Языки и адреса

Нужны полноценные русская и английская версии: интерфейс, содержимое и метаданные страниц.

| Адрес | Выбор языка | Поведение переключателя |
| --- | --- | --- |
| `/` | По основному языку браузера: русский → RU, английский и неподдерживаемые языки → EN | Меняет язык, оставляя URL `/` |
| `/ru/` и русские страницы проектов | Русский, независимо от языка браузера | Открывает соответствующую английскую страницу |
| `/en/` и английские страницы проектов | Английский, независимо от языка браузера | Открывает соответствующую русскую страницу |

При переключении между явными языковыми адресами сохраняется текущая страница проекта. Исключение с неизменным адресом относится к корневой `/`.

Корневая `/` **также доступна для индексации**. Предложение поставить ей `noindex` явно отклонено владельцем. Автоматически перенаправлять её на языковой адрес не требуется.

## Индексация

- Использовать обычные адреса страниц вместо hash-навигации референса.
- Предоставлять готовый HTML при сборке, включая содержимое локализованных страниц.
- Подготовить локализованные заголовки и описания, canonical, языковые альтернативы `hreflang`, sitemap и метаданные для публикации ссылок в соцсетях.
- Не вводить запрет индексации корневой страницы.
- Точные правила canonical и HTML-язык первоначальной статической версии `/` определить в спецификации с учётом клиентского определения языка. Индексируемость и отсутствие изменения URL на `/` — обязательные ограничения.

## Технологические решения

- Vue 3, TypeScript, Nuxt, Tailwind CSS и pnpm.
- Tailwind CSS — основной инструмент вёрстки, адаптивности и оформления всех страниц и общих элементов. Дизайн по-прежнему опирается на исходный референс, включая звёздный фон и анимацию кита.
- Статическая генерация страниц Nuxt.
- Контент в файлах: JSON или типизированные константы. Изображения, PDF и прочие статические материалы — в `public`.
- База данных не используется.
- Маленькому проекту нужны поддерживаемая структура и минимально достаточный набор зависимостей. Дополнительные библиотеки и их версии пока не выбраны.

## Размещение

Согласован вариант: арендованный VPS с Docker и Caddy. Nuxt генерирует готовый сайт при сборке; Caddy раздаёт статические файлы и обеспечивает HTTPS для `jefrry.dev`. Постоянно работающий сервер приложения для согласованных функций не требуется.

Обновление контента предполагает пересборку сайта. Провайдер, тариф и конкретная схема доставки на сервер пока не выбраны; покупка хостинга и развёртывание в этом интервью не выполняются.

### Дополнение: GitHub CI/CD

По последующему запросу владельца в объём проекта включена настройка GitHub Actions: проверки, сборка и автоматизированная доставка контейнера на выбранный VPS. Это отдельный седьмой тикет после подготовки сайта и Docker/Caddy. Секреты и доступы задаются вне репозитория; покупка сервера и настройка аккаунта провайдера в задачу не входят. Сейчас создаётся только документация этой работы, pipeline и деплой не запускаются.

## Детали для будущей спецификации

Это вопросы реализации, а не оставшиеся несогласованными цели продукта:

- Точная структура контента, маршрутов и компонентов, включая выключаемые страницы статей.
- Первоначальный статический HTML `/`, метаданные и canonical при смене языка без смены URL.
- Нужна ли память ручного выбора языка между посещениями: такое поведение не запрашивалось и не согласовано.
- Конкретные тестовые материалы проектов и статей, английские переводы.
- Конфигурация Docker/Caddy, параметры выбранного VPS и необходимые доступы для GitHub Actions. Само требование CI/CD добавлено владельцем после интервью.

Даты и факты опыта сохраняются из исходника. В нём текущая работа под NDA обозначена как «Апрель 2026»; уточнение окончания или расширение периода владельцем не предоставлено, поэтому самостоятельно менять запись нельзя.
