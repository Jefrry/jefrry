# jefrry.dev — портфолио и резюме

Статус: проект спецификации по итогам grill-with-docs, дополненный требованиями Tailwind CSS и GitHub CI/CD. Продуктовые требования согласованы; предложенный подход к будущему тестированию ожидает подтверждения владельца. Настроен локальный Markdown-трекер; исходный документ сохраняется здесь.

## Problem Statement

Егору Ильину нужен персональный сайт, который помогает работодателям и потенциальным заказчикам-нанимателям понять его специализацию, изучить опыт и навыки, посмотреть проекты портфолио, получить резюме и связаться с ним.

Готовый макет уже задаёт визуальное направление, но представляет собой HTML/CSS/JavaScript с hash-навигацией, русскими текстами и данными внутри кода отрисовки. Его нужно превратить в поддерживаемый проект с русской и английской языковыми версиями, готовыми для индексации страницами и простым обновлением содержимого. Владелец не хочет использовать базу данных или отдельную систему управления контентом.

## Solution

Создать адаптивный сайт на Vue 3, TypeScript и Nuxt с Tailwind CSS, pnpm и статической генерацией. Tailwind CSS использовать как основной инструмент вёрстки и оформления. Использовать существующий макет как референс: сохранить тёмную палитру, звёздный фон и плавно движущегося кита, улучшая удобство и доступность по необходимости.

Главная представляет автора и сохраняет факты исходного макета. Каталог и подробные страницы проектов используют легко заменяемые тестовые проекты, явно названные и описанные как тестовые. Заготовки раздела статей существуют, но раздел полностью выключен. Обе языковые версии дают существующее русское PDF-резюме, с возможностью позже назначить отдельный английский файл.

Русская и английская версии имеют постоянные адреса. Корневая страница выбирает язык браузера и позволяет переключить его без изменения адреса. Все три входа доступны для индексации. Готовые файлы сайта обслуживает Caddy в Docker на VPS с доменом jefrry.dev.

## Implementation Decisions

### Стек и режим работы

- Использовать Vue 3, TypeScript в строгом режиме, Nuxt, Tailwind CSS и pnpm. Конкретные поддерживаемые версии зафиксировать при реализации вместе с lockfile; произвольное расширение набора зависимостей не требуется.
- Подключить Tailwind CSS с первого законченного среза сайта и использовать для компоновки, адаптивности, типографики, цветов и состояний элементов на всех страницах. Общие параметры оформления должны быть согласованы с визуальным референсом. Дополнительный CSS допустим для анимаций и декоративных эффектов, когда он нужен для сохранения дизайна.
- Генерировать HTML всех публикуемых страниц при сборке. Страница должна содержать основной текст и ссылки до выполнения JavaScript; интерактивность подключается после загрузки.
- Не вводить базу данных, CMS или постоянно работающий сервер приложения. Изменения контента и настроек разделов применяются новой сборкой.
- Результат сборки должен содержать необходимые изображения, шрифты и PDF. Сохранять исходный референс отдельно; не зависеть от него при обслуживании готового сайта.

### Модули и их интерфейсы

- Модуль содержимого предоставляет типизированные данные профиля, опыта, технологий, образования, интересов, контактов, проектов портфолио и статей. Отображающие модули получают эти данные, а не содержат копии текстов.
- Модуль языковых версий определяет активный язык и адрес соответствующей страницы другого языка. Различие поведения корневой страницы и явных языковых адресов сосредоточено здесь.
- Модуль представления включает общую оболочку с шапкой, переключателем языка, навигацией, основным содержимым и контактами, а также главную, каталог и страницу проекта, заготовки статей и страницу ошибки.
- Модуль метаданных и публикации использует ту же модель публикуемых страниц для генерации адресов, canonical, языковых альтернатив и sitemap. Выключенные статьи исключаются из этой модели.
- Конфигурация размещения собирает сайт и обслуживает статический результат через Caddy. Добавлять дополнительные слои ради возможных будущих интеграций не требуется.

### Контент и данные

- Допустимы JSON и типизированные константы. Изображения, PDF и другие статические материалы хранятся как публичные файлы. Замена содержимого не требует изменения разметки.
- Проект портфолио имеет стабильный идентификатор адреса, категорию, технологии, обложку и русские/английские название, краткое описание, подробное описание и контекст. Период, результаты и внешние ссылки могут быть необязательными.
- Подготовить шесть тестовых проектов, сохранив исходную плотность каталога. Использовать категории Fullstack, Frontend и учебные/личные проекты, представленные в референсе.
- Тестовый характер каждого проекта прямо указан в названии и описании на обоих языках. Отдельную плашку не добавлять. Не использовать реальные коммерческие проекты как тестовые данные и не выдумывать профессиональные достижения автора.
- Карточки и подробные страницы получают сведения из одной записи проекта. Если подборка проектов присутствует на главной, она использует тот же набор данных; добавление новой подборки не является обязательным требованием.
- Сведения профиля и опыта перенести из референса, сохранив смысл, даты и заявленные результаты. Перевод на английский не должен добавлять факты.
- Для PDF предусмотреть независимые ссылки по языкам, первоначально ведущие на один существующий русский документ. Подпись должна позволять понять язык доступного файла.
- Статья имеет стабильный идентификатор адреса, дату, локализованные название, краткое описание и основное содержимое. Подготовить как минимум одну тестовую статью для заготовок списка и подробной страницы.

### Маршруты и языковые версии

- Использовать обычные маршруты: корневой вход `/`, главные `/ru/` и `/en/`, локализованные каталоги проектов и страницы отдельных проектов. Hash допускается для якорей внутри страницы, а не для маршрутизации между страницами.
- Идентификатор одного проекта одинаков в обеих языковых версиях. Прямое открытие и перезагрузка локализованного маршрута работают независимо от предшествующей навигации.
- Явный языковой адрес имеет приоритет над языком браузера. Переключение открывает эквивалент текущей страницы на другом языке.
- На `/` первоначальное статическое представление — русское, по языку исходного макета. После подключения приложения выбирается основной язык браузера: русский, включая региональные варианты, → RU; остальные → EN. Это техническое уточнение спецификации для совместимости статической сборки и браузерного выбора языка.
- На `/` переключатель изменяет содержимое, язык документа и локализованные метаданные без изменения адреса. Ссылки из корневой страницы в каталог и проекты ведут на явные адреса выбранного языка.
- Сначала клиент использует то же состояние, что и статический HTML, затем применяет язык браузера. Основное содержимое не скрывается до определения языка.
- Сохранять ручной выбор языка между отдельными посещениями не требуется. Пока посетитель остаётся на `/`, его выбор не переопределяется повторно при обычных обновлениях состояния страницы.
- Неизвестные языковые префиксы и отсутствующие проекты возвращают HTTP 404 с понятным интерфейсом. Не превращать произвольные неизвестные адреса в главную с HTTP 200.

### Индексация и метаданные

- Корневая и явные языковые страницы разрешены для индексации. Не добавлять им `noindex` и не запрещать их обход правилами robots.
- У `/` собственный canonical на основной домен без перенаправления на языковую версию. Canonical корневой страницы не меняется при клиентском переключении языка.
- У каждой публикуемой локализованной страницы собственный canonical. Выбрать единый формат завершающего слеша, использовать его во внутренних ссылках, canonical и sitemap, а альтернативную форму нормализовать при обслуживании сайта.
- Для существующих эквивалентных страниц указать взаимные языковые альтернативы RU и EN. Для главных страниц также указать корневой вход как `x-default`; для проектов не назначать главную эквивалентом страницы проекта.
- Русский исходный HTML `/` имеет русские метаданные. После клиентского выбора языка обновляются язык документа, заголовок, описание и отображаемое содержимое; корневой canonical остаётся прежним. Для явных адресов всё это определяется языком URL уже при сборке.
- Sitemap включает `/`, обе явные языковые главные, каталоги и все публикуемые проекты. Выключенные статьи и несуществующие адреса отсутствуют.
- Подготовить уникальные заголовки и описания по содержимому страницы, а также Open Graph и сведения для предпросмотра ссылок. Использовать абсолютные адреса основного домена для метаданных и sitemap.
- Индексируемость является требованием к доступности страниц для поисковых систем, а не обещанием позиции в выдаче или фактического включения каждого адреса в индекс.

### Выключенный раздел статей

- Одна настройка сборки определяет доступность раздела; первоначальное значение — выключен.
- При выключении отсутствуют навигация, блоки, карточки и ссылки на статьи во всех языковых версиях и на `/`.
- Страницы статей не регистрируются как доступные маршруты, не генерируются как публикуемые документы и отсутствуют в sitemap. Прямое обращение к ним возвращает HTTP 404.
- Заготовки каталога и подробной страницы и их тестовое содержимое сохраняются в исходниках. После включения и пересборки обе страницы доступны на явных языковых адресах и получают обычные локализованные метаданные.

### Представление и доступность

- Оформление главной, проектов, заготовок статей, страницы ошибки и общей оболочки строится на Tailwind CSS и общих параметрах темы. Использование Tailwind не заменяет требования к внешнему виду, доступности и анимации кита.
- Сохранить узнаваемость референса, включая плавающего кита. Допустимы улучшения адаптивности и композиции; точное совпадение каждого пикселя не требуется.
- Анимация кита плавная и циклическая; она не меняет компоновку и не мешает чтению. При системном уменьшении движения декоративное движение отключается или существенно уменьшается.
- Обеспечить семантические заголовки и области страницы, видимый фокус, клавиатурную доступность, понятные названия кнопок и состояние активного языка/фильтра.
- Фильтры меняют видимый набор проектов без перезагрузки страницы. Для пустого результата предусмотрено понятное сообщение; переключение языка не меняет смысл выбранной категории.
- На узком экране доступны навигация, язык, контакты и PDF, а контент не требует горизонтальной прокрутки.
- Контакты используют существующие ссылки Telegram, GitHub и email. Отдельная форма отправки сообщений не нужна.

### Размещение и сопровождение

- Подготовить воспроизводимую сборку в Docker и конфигурацию Caddy для раздачи статических файлов на VPS с HTTPS для основного домена.
- HTTPS предполагает настроенный DNS и доступность необходимых сетевых портов. Хранилище состояния сертификатов должно переживать пересоздание контейнера.
- Обновление — пересборка и замена результата сайта. Статические файлы и клиентские ресурсы одной сборки поставляются вместе; длительное кеширование допустимо для ресурсов с версией в имени, но не должно удерживать устаревший HTML после обновления.
- Документировать локальный запуск, сборку, замену контента и PDF, включение статей и запуск контейнера. Самостоятельное обновление владельцем не должно требовать знакомства с внутренностями отображающих модулей.

### GitHub Actions: проверки, сборка и деплой

- Требование CI/CD добавлено владельцем после первоначального разбиения работ. Настройку выделить в отдельный тикет, зависящий от готовой модели публикуемых страниц и контейнерного запуска.
- Для pull request запускать установку зависимостей с зафиксированным lockfile, проверку TypeScript, поведенческие тесты и статическую сборку. Pull request не запускает production-деплой и не получает секреты сервера.
- После изменения основной ветки публиковать только версию, успешно прошедшую те же проверки. Поддержать ручной повторный запуск доставки известной версии без изменения исходников.
- Контейнер помечается идентификатором коммита. На VPS доставляется проверенная версия, а не новая сборка произвольного состояния ветки. Конкретный способ хранения и передачи образов зафиксировать при реализации.
- Деплой обновляет приложение через согласованный Docker/Caddy и проверяет HTTP-доступность главной, локализованной вложенной страницы, PDF и неизвестного адреса. Одновременно не выполняются две конкурирующие доставки на один сервер.
- Документировать параметры сервера, необходимые секреты и их назначение, проверку подлинности SSH-хоста, диагностику неуспешного обновления и возврат к предыдущей версии. Пароли, приватные ключи и токены не хранятся в репозитории и не печатаются в журнал.
- Отсутствие реальных доступов не препятствует подготовке pipeline, его конфигурации и воспроизводимой проверки на локальном/тестовом целевом окружении. Реальная публикация требует предоставленного VPS и доступов; не заявлять её успешной по одному факту наличия workflow.

## Testing Decisions

Статус этого раздела: предложенный подход, ожидающий подтверждения владельца по процессу to-spec. Здесь описаны будущие проверки; в рамках подготовки спецификации они не выполняются.

- Основной seam — публичный сайт после статической сборки, обслуживаемый HTTP-сервером с теми же правилами маршрутизации, что и при размещении. Наблюдения выполняются браузером и прямыми HTTP-запросами к одному и тому же интерфейсу, без доступа к внутреннему состоянию модулей.
- Предпочтительный инструмент браузерных сценариев — Playwright. Проверки исходного HTML, HTTP-статусов и sitemap дополняют сценарии на том же seam; отдельные внутренние точки подмены модулей для этого не нужны.
- Хороший тест проверяет наблюдаемый результат: доступный текст, выбранный язык, URL, рабочую ссылку, состояние фильтра, код ответа или метаданные. Он не закрепляет имена компонентов, структуру внутренних функций, количество вызовов и технические CSS-классы.
- Модули языковых версий, представления, контента и метаданных проверяются совместно через опубликованное поведение. Перенос текста между внутренними модулями не должен ломать тесты, если результат сайта прежний.
- Приоритетные сценарии языка: первое открытие `/` с русским, английским и неподдерживаемым языком браузера; региональный русский вариант; ручное переключение на `/` с неизменным URL; явный префикс при противоположном языке браузера; переключение на странице одного проекта; перезагрузка прямого адреса.
- Приоритетные сценарии индексации: получение содержательного HTML без JavaScript, корректный язык и метаданные явных страниц, self-canonical корневой, взаимные языковые альтернативы, наличие нужных адресов в sitemap и отсутствие запрета индексации `/`.
- Каталог: фильтрация, восстановление всех проектов, сообщение при отсутствии совпадений, переход карточка → подробности → каталог и единые данные карточки/подробностей.
- Выключенные статьи: отсутствие ссылок во всех общих областях и на главных, отсутствие в sitemap, HTTP 404 на каталоге и отдельной статье. Дополнительная сборка с включённым разделом проверяет доступность заготовок и локализованных страниц.
- Резюме и контакты: обе языковые версии ведут на доступный существующий PDF; отдельная замена английского назначения не меняет русское; Telegram, GitHub и email сохраняют корректные назначения.
- Обновление контента: контрольная замена записи проекта с пересборкой обновляет его карточку, подробности и при необходимости список генерируемых адресов без изменения отображающего кода.
- Доступность и адаптивность: репрезентативный узкий и широкий экран, отсутствие горизонтальной прокрутки, клавиатурная навигация, видимый фокус, состояние активных элементов и режим уменьшенного движения.
- Размещение: прямой запрос вложенной страницы и PDF, HTTP 404 неизвестного адреса, выдача полного набора ресурсов одной сборки. HTTPS и домен проверяются при будущем развёртывании, а не требуют реальных сертификатов для каждого локального браузерного теста.
- CI/CD: ошибочная проверка запрещает доставку, pull request не вызывает production-деплой, успешный запуск доставляет образ соответствующего коммита, проверяется доступность обновлённой версии и воспроизводимость возврата к предыдущей. При отсутствии VPS отделять проверки подготовленного механизма от ещё не выполненной реальной публикации.
- Предыдущих тестов, приложения на Nuxt и готовой тестовой инфраструктуры в репозитории нет. HTML/CSS/JavaScript-макет — источник ожидаемого вида и исходного содержимого, но не пример тестовой архитектуры.
- Точную визуальную оценку относительно референса провести на этапе реализации; не привязывать всю проверку поведения к полноэкранным снимкам или случайным значениям анимации.

## Out of Scope

- База данных, CMS, административная панель, регистрация, личные кабинеты и серверные бизнес-функции.
- Форма обратной связи, доставка email и новые интеграции с внешними сервисами.
- Поиск по статьям, сложная редакционная система и публикация раздела статей в первой версии.
- Подготовка настоящих кейсов вместо тестовых проектов и выдумывание достижений автора.
- Создание нового английского PDF-резюме.
- Запоминание языка между посещениями, дополнительные языки и географическое определение языка.
- Покупка или выбор конкретного тарифа VPS, настройка аккаунта провайдера и фактическое подключение домена в рамках подготовки проекта.
- Дополнительные CI/CD-платформы помимо выбранного GitHub Actions, отдельные preview-окружения для каждого pull request и оркестрация нескольких серверов.
- Гарантии позиций в поисковой выдаче или фактической индексации поисковой системой.
- Написание кода приложения, установка зависимостей, создание тикетов, запуск тестов, валидация и развёртывание в текущем этапе to-spec.

- Настроен локальный Markdown-трекер со стандартными triage-статусами. Тикеты сохраняются отдельно со статусом `ready-for-agent`; внешний трекер для задач не используется. GitHub Actions используется для CI/CD независимо от места хранения тикетов.
