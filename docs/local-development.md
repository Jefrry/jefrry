# Локальная разработка

Главная с русской и английской языковыми версиями реализована на Vue 3 и Nuxt со строгим TypeScript и Tailwind CSS. Сайт генерируется в статические файлы и не требует базы данных или сервера приложения.

## Требования и запуск

Нужны Node.js 22.12 или новее и pnpm 12.6.0 (версия закреплена в `package.json`).

```sh
pnpm install --frozen-lockfile
pnpm dev
```

Адрес разработки: `http://127.0.0.1:3000`.

## Проверка типов и статическая сборка

```sh
pnpm typecheck
pnpm generate
```

Результат сборки находится в `.output/public/`: готовый HTML `/`, `/ru/` и `/en/`, каталогов `/ru/projects/` и `/en/projects/`, всех проектов на обоих языках, страница `404.html`, изображения, русский PDF, шрифты Manrope и клиентские ресурсы. Для размещения достаточно этой папки. Исходная папка `portfolio-v2-stars/` нужна только как референс при разработке; сборка и готовый сайт её не используют.

На статическом хостинге неизвестный адрес должен выдавать `404.html` со статусом HTTP 404. Не включайте перенаправление всех неизвестных адресов на `index.html` или `200.html`: оно скроет ошибки адресов. [Запуск через Docker и Caddy, обновление и откат](deployment.md) описаны отдельно. Для разработки используется `pnpm dev`, для контейнерного просмотра и размещения — Caddy с готовыми статическими файлами.

Автоматические тесты и тестовые зависимости не добавляются по решению владельца. Доступные технические проверки — линтер, TypeScript и статическая сборка.

## Форматирование шаблонов

Между соседними HTML-элементами и компонентами Vue-шаблона обязательна пустая строка. Правило `vue/padding-line-between-tags` настроено в `eslint.config.mjs`; его нарушение считается ошибкой линтера.

```sh
pnpm lint
pnpm lint:fix
```

Первая команда проверяет исходники, вторая автоматически исправляет форматирование. Генерируемые файлы и исходный референс исключены из проверки.

## Обновление содержимого

Исходники сгруппированы по сущностям внутри технических папок `constants`, `types`, `composable`, `components`, `utils` и `views`. Подпапка создаётся там, где у сущности есть соответствующие файлы:

| Подпапка | Содержимое |
| --- | --- |
| `articles` | Статьи, их переводы, логика и представления |
| `projects` | Проекты портфолио, подписи каталога, типы и логика |
| `profile` | Профиль автора, резюме, контакты, навыки и секции представления |
| `experience` | Опыт работы, его типы и отображение |
| `language` | Языковая версия, выбор языка и построение адресов |
| `site` | Общая навигация, главная, оформление, ошибки и публикуемые адреса |

Служебные точки входа Nuxt (`app.vue`, `error.vue`, `layouts`, `pages`, `plugins`) сохраняют предусмотренное фреймворком расположение. Подпапки `composable/**` и `utils/**` подключены к автоимпортам в `nuxt.config.ts`.

- `app/constants/profile/profile.ts` — имя, специализация, местоположение, представление, навыки, контакты и отдельное назначение PDF для каждой версии (`PROFILES.ru.resume` и `PROFILES.en.resume`).
- `app/constants/experience/experiences.ts` — периоды, компании, роли, описания, результаты и полный стек опыта. Английские переводы привязаны к компании; общий стек и роли берутся из русских данных. Дата NDA сохранена из референса как «Апрель 2026».
- `app/constants/site/translations.ts` — тексты интерфейса, подписи управления, заголовки и описания обеих языковых версий.
- `app/constants/projects/projects.ts` — единые записи проектов портфолио: стабильный `id`, категория (`fullstack`, `frontend`, `personal`), технологии, путь обложки и содержимое `content.ru`/`content.en`. Карточка, подробности и список генерируемых адресов используют эту запись. Чтобы добавить или заменить проект, редактируйте данные и пересоберите сайт; разметку и конфигурацию адресов менять не нужно. Для обоих языков сохраняйте один `id` из латинских букв, цифр и дефисов, уникальный в списке.
- `app/constants/projects/projectTranslations.ts` — подписи каталога и подробностей на двух языках. `public/assets/projects/` — обложки, заданные полем `cover`.
- `app/types/` — типы содержимого и параметров компонентов в подпапках соответствующих сущностей.
- `app/composable/projects/` — `useProjectCatalog` управляет фильтрами категорий и карточками; `usePortfolioProject` выбирает локализованные подробности и проверяет адрес проекта.
- `app/composable/language/useLanguage.ts` — язык и адреса навигации, доступ к локализованным данным.
- `app/composable/site/` — `useSite` применяет язык браузера и язык документа; `usePageMetadata` задаёт метаданные публикуемых страниц; `useErrorPage` готовит содержимое страницы ошибки. Страницы и компоненты получают готовые данные и действия из composable-функций.
- `app/components/site/Header.vue` и `app/components/site/Footer.vue` — общие компоненты, подключённые в `app/layouts/default.vue`.
- `app/components/profile/` — представление автора и его навыков; `app/components/experience/` — секция опыта и отдельная запись опыта.
- `app/views/site/HomePage.vue` — общая главная, используемая корневым и языковыми маршрутами. `app/components/site/WhaleVisual.vue` — декоративное изображение кита.
- `public/assets/egor-ilin-resume.pdf` — исходный русский документ. Обе версии пока ссылаются на него с явной подписью языка. Для английского документа добавьте новый файл и измените только `PROFILES.en.resume.href` и `label`; для русского — `PROFILE.resume`.
- `public/assets/whale.png` и `public/assets/stars.svg` — изображения референса.
- `app/assets/css/main.css` — палитра, шрифтовая тема, звёздный фон и анимация кита. Основное оформление и адаптивность заданы классами Tailwind в шаблоне главной.

После изменения содержимого или материалов снова выполните `pnpm generate`. В раскрывающихся блоках опыта используется стандартный HTML `details`: результаты доступны без JavaScript, блоки управляются клавиатурой. Движение кита отключается системной настройкой уменьшения движения.

## Языковые адреса

`/ru/` и `/en/` задают язык независимо от языка браузера. Переключатель открывает соответствующий адрес другого языка, сохраняя путь, параметры и якорь. Общая функция `app/utils/language/language.ts` используется также для каталогов и страниц `/ru/projects/<id>/` и `/en/projects/<id>/`.

Исходный HTML `/` русский. После подключения приложения основной язык браузера (`navigator.language`) выбирает русский для `ru` и региональных вариантов вроде `ru-RU`; для английского и неподдерживаемых языков выбирается английский. Выбор выполняется после гидратации, без скрытия содержимого и перенаправлений. На `/` кнопки RU/EN меняют содержимое, язык документа и метаданные на месте, включая адрес с якорем. Обычные обновления не сбрасывают ручной выбор. После перезагрузки снова используется язык браузера; cookies и localStorage для языка не используются.

Неизвестные языковые префиксы не проходят проверку маршрута Nuxt и не генерируются. При размещении статической сборки HTTP 404 для них обеспечивает хостинг по правилу выше. Корневая страница остаётся индексируемой и имеет постоянный canonical `https://jefrry.dev/`.

## Индексация и предпросмотр ссылок

Основной домен и общее изображение предпросмотра заданы в `app/constants/site/site.ts`. Главные, каталоги, проекты и включённые статьи используют `usePageMetadata`: локализованные title/description, Open Graph, Twitter, абсолютный canonical без параметров и якоря, взаимные RU/EN-ссылки. Для трёх главных дополнительно задан `x-default` на `/`; у вложенных страниц альтернативы ведут на эквивалентное содержимое. Язык документа и метаданные `/` обновляются вместе с содержимым, canonical остаётся прежним. Исходный HTML полноценный и русский.

`nuxt.config.ts` получает публикуемые страницы из `getPublishedPages(ARTICLE_ROUTES)`. Этот единственный список используется статической генерацией и `/sitemap.xml`; данные проектов и метаданные включённого объекта маршрутов статей автоматически обновляют оба результата при пересборке. `/robots.txt` разрешает обход и указывает sitemap. Серверные обработчики нужны при разработке и сборке: в `.output/public/` сохраняются готовые `sitemap.xml` и `robots.txt`, сервер приложения при размещении не требуется.

Конфигурация обычным импортом читает описания страниц из `app/constants/articles/articleRoutes.ts` и регистрирует их через `pages:extend`. Описания содержат пути `file`, а не импорты Vue-представлений, поэтому конфигурация не требует отдельного загрузчика TypeScript. Минимальная версия Node.js остаётся 22.12.

### Контракт адресов для контейнерного обслуживания (06)

- Основной origin — `https://jefrry.dev`. Внутренние ссылки относительны этому origin; canonical, языковые альтернативы, изображения предпросмотра и sitemap абсолютны.
- Адреса HTML-страниц заканчиваются `/`, включая каталоги и подробности. Хостинг должен перенаправлять существующий адрес без завершающего слеша на вариант со слешем постоянным редиректом 308, сохраняя параметры запроса. Это относится и к `/ru` и `/en`. Несуществующие адреса остаются HTTP 404.
- HTTP и альтернативные имена хоста перенаправляются на HTTPS основного домена с сохранением пути и параметров запроса. На `/` нет перенаправления по языку браузера.
- Адреса файлов (`/sitemap.xml`, `/robots.txt`, PDF, изображения и ресурсы сборки) сохраняют расширение и не получают завершающий слеш.
- Вложенный адрес отдаёт свой `index.html`; неизвестный — `404.html` со статусом 404. Запрещён общий успешный fallback на `/index.html` или `/200.html`, в том числе для выключенных статей. Приложение не добавляет запрет индексации `/`.

Каталог фильтруется без перезагрузки по категории. Параметр `category` сохраняется в адресе, при смене языка и при возврате из подробностей. Сброс восстанавливает все записи. Необязательные `results` и `period` задаются внутри языкового содержимого, `externalUrl` — в общей записи; если поле не заполнено, соответствующий блок не выводится. Два текущих тестовых проекта не имеют внешних назначений, поэтому выдуманные ссылки не показываются.

Кнопки категорий временно закомментированы в шаблоне каталога по решению владельца. Логика категорий в `useProjectCatalog` сохранена: параметр `category` в адресе продолжает работать, доступен сброс пустого результата. Чтобы вернуть кнопки, снимите комментарий с блока в `app/pages/[language]/projects/index.vue`. Поиск полностью удалён: поля ввода, поискового состояния и фильтрации по `q` нет.

## Выключенный раздел статей

Раздел подключается одним объектом в массиве `ARTICLE_ROUTES` файла `app/constants/articles/articleRoutes.ts` через хук регистрации `pages:extend` в `nuxt.config.ts`. Сейчас объект целиком закомментирован с помощью `/* ... */`. Для включения добавьте в начало этого файла `import { ARTICLES } from './articles';`, удалите два маркера комментария и выполните `pnpm generate`; для выключения закомментируйте объект, удалите импорт и пересоберите сайт. Отдельного флага и хука удаления маршрутов нет. Каталог и статья находятся вне `app/pages/`, поэтому Nuxt не регистрирует их автоматически. Навигация проверяет наличие маршрута каталога.

После включения или выключения раздела перезапустите работающий `pnpm dev`: список страниц и адресов sitemap читается при запуске Nuxt. Для публикации достаточно пересборки.

При выключении маршруты статей не регистрируются, в общей навигации нет ссылок на раздел, а каталог и подробности не попадают в статическую сборку. Прямые запросы `/ru/articles/`, `/en/articles/` и вложенных адресов должны получать HTTP 404 по общему правилу хостинга, описанному выше. При размещении заменяйте всю папку готовой сборки, чтобы не сохранять страницы от предыдущей включённой версии.

При включении доступны локализованные каталоги `/ru/articles/`, `/en/articles/` и статья `test-first-note` на обоих языках. Переключатель сохраняет идентификатор статьи; ссылка над статьёй возвращает в каталог текущего языка. Дата отображается в формате языка страницы с фиксированным UTC, чтобы результат не зависел от часового пояса браузера или сборки.

- `app/constants/articles/articles.ts` — записи с общим `id`, датой `date` в формате `YYYY-MM-DD`, заголовком, описанием и разделами основного текста в `content.ru` и `content.en`. Тестовое содержимое, включая дату, предназначено для замены. Новый `id` должен быть уникальным и состоять из латинских букв, цифр и дефисов.
- `app/constants/articles/articleTranslations.ts` — подписи каталога и возврата на двух языках.
- `app/composable/articles/useArticles.ts` — локализация записей, даты, адреса, выбор статьи, проверка маршрута и основные метаданные.
- `app/views/articles/` — представления каталога и статьи с общей темой и Tailwind CSS.
- `app/constants/articles/articleRoutes.ts` — описания каталога и статьи одним объектом с дочерними маршрутами, путями файлов представлений и метаданными `publishedPages` с локализованными адресами. `nuxt.config.ts` регистрирует их через `pages:extend`; проверка идентификатора статьи задана в `definePageMeta` её представления.
- `app/constants/site/publishedPages.ts` — общий источник адресов публикуемых страниц. `getPublishedPages(ARTICLE_ROUTES)` возвращает основные страницы, проекты и адреса явно подключённых маршрутов из метаданных. `nuxt.config.ts` передаёт этот список статическому генератору и обработчику sitemap. Закомментированный объект не добавляет адресов независимо от наличия контента статей.
