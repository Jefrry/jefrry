# 06: Запуск и обновление сайта через Docker и Caddy

**What to build:** Владелец воспроизводимо собирает контейнер и запускает статический сайт с Caddy, получает рабочие прямые адреса, PDF и понятные ошибки. Конфигурация подготовлена к HTTPS на jefrry.dev и к дальнейшей автоматизации обновлений.

**Blocked by:** 02 — Русская и английская языковые версии.

**Status:** ready-for-agent

- [x] Docker-сборка использует зафиксированные версии среды, pnpm и lockfile, генерирует сайт и включает готовые HTML, клиентские ресурсы, изображения, шрифты и PDF без зависимости от папки референса на сервере.
- [x] Готовый сайт раздаётся Caddy без постоянно работающего процесса приложения Nuxt и без базы данных. Подготовлены параметры запуска на VPS и основного домена.
- [x] Прямое открытие и перезагрузка вложенных статических страниц работают; общий механизм раздаёт и страницы, добавленные в последующих тикетах, без ручного перечня каждого маршрута в серверной конфигурации.
- [x] Неизвестный адрес возвращает HTTP 404. Клиентский fallback не превращает отсутствующие проекты, языки и выключенные статьи в успешные страницы.
- [x] Формат адресов поддерживает единообразие завершающего слеша; правила можно согласовать с метаданными из 05 без переделки механизма раздачи.
- [x] Конфигурация готова к HTTPS при настроенном DNS и доступных необходимых портах. Состояние сертификатов сохраняется при пересоздании контейнера, production-секреты не включены в образ.
- [x] Обновление поставляет HTML и ресурсы одной сборки вместе. Кеширование не удерживает прежний HTML после обновления; длительное кеширование применяется только к ресурсам с версией в имени.
- [x] Есть инструкция локального контейнерного запуска, размещения на подготовленном VPS, ручного обновления, замены контента и PDF, включения статей и возврата к предыдущей версии контейнера.
- [x] На локальном или тестовом контейнере проверены корневая и языковые страницы, вложенный прямой адрес, PDF, необходимые ресурсы и HTTP 404. Наличие конфигурации HTTPS не выдаётся за проверенное подключение реального домена.

## Scope notes

Может выполняться независимо от 03 и 04 после 02: сервер раздаёт результат сборки по общим правилам. В 07 проверяется доставка полного сайта вместе с адресами из 05. Покупка VPS, настройка аккаунта провайдера и реализация GitHub Actions в этот тикет не входят.
