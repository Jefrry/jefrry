# 07: GitHub Actions — проверки, сборка и деплой

**What to build:** Владелец видит результаты проверок и сборки в GitHub и вручную запускает production workflow для проверенной версии основной ветки. Workflow публикует образ в GHCR и доставляет его на подготовленный VPS по точному digest, как в post-sentry. Можно установить опубликованный коммит, диагностировать ошибку и вернуть предыдущую версию. Ручной запуск заменяет первоначальное требование автоматической доставки после push по уточнению владельца от 29.10.2026.

**Blocked by:** 05 — Индексация и предпросмотр ссылок; 06 — Запуск и обновление сайта через Docker и Caddy.

**Status:** ready-for-agent

- [x] Для pull request и изменений основной ветки выполняются установка по lockfile и ESLint с согласованными версиями Node.js и pnpm. По уточнению владельца от 29.10.2026 это единственная проверка CI/CD; TypeScript, тесты и проверочная статическая сборка из CI удалены. Production-образ собирается отдельно при ручном деплое.
- [x] Ошибка любой обязательной проверки запрещает production-деплой. Pull request, включая внешний, не запускает доставку на сервер и не получает production-секреты.
- [x] После успешных проверок основной ветки собирается и сохраняется контейнерная версия, однозначно связанная с идентификатором коммита. Способ хранения и передачи образов документирован.
- [x] На VPS доставляется образ проверенного коммита, а не повторно собранное произвольное состояние ветки. Обновление использует механизм Docker/Caddy из 06.
- [x] Ошибка доставки отражается как неуспешный результат. По уточнению владельца от 29.10.2026 автоматические HTTP-проверки из CI/CD удалены; доступность страниц, PDF и HTTP 404 владелец проверяет вручную по инструкции.
- [x] Конкурирующие доставки на один сервер сериализованы; более старый запуск не перезаписывает уже опубликованную более новую версию. Поддержан ручной повторный запуск для известного коммита.
- [x] Параметры сервера, доступ для доставки и при необходимости реестра задаются через настройки и секреты GitHub. Секреты не записываются в репозиторий, образ или журналы; SSH-подключение проверяет подлинность сервера.
- [x] Документированы первичная подготовка целевого VPS, необходимые секреты и переменные, права доступа, поиск опубликованной версии, диагностика сбоя и процедура возврата к предыдущему доступному образу.
- [ ] На доступном тестовом целевом окружении проверены успешная доставка и отказ при ошибке обязательной проверки; проверено, что pull request не доставляет production-версию. Воспроизводимый сценарий возврата к предыдущему образу описан и проверен при наличии целевого окружения.
- [x] Если реальный VPS или доступы ещё не предоставлены, подготовлены pipeline и инструкции, а непроверенный production-деплой явно отмечен. Реальная публикация не считается выполненной по одному наличию конфигурации.

## Scope notes

Зависимость от 05 обеспечивает готовность всех адресов и проверок публикуемого сайта; зависимость от 06 обеспечивает воспроизводимый образ и контракт запуска. Трекер задач остаётся локальным — GitHub используется для CI/CD. Покупка сервера, дополнительные CI-платформы и отдельные preview-окружения не входят в задачу. Тикет описывает будущую реализацию: его создание не запускает workflow, загрузку секретов или публикацию.
